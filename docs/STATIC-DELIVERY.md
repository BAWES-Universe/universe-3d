# Static asset delivery

The built-in HTTP server serves verified precompressed public assets and supports
ETag revalidation. This reduces static transfer bytes and repeated downloads without relying on
an external proxy. It does not change authenticated APIs, uploaded room files/images,
SSE, deployment settings or application rendering.

## Build contract

`npm run build` still produces the mutable `/main.js`, `/main.css` and copied
public entry assets. Esbuild-generated split chunks now use
`chunks/[name]-[hash]`. The build writes smaller `.br` and `.gz` sidecars for text
assets of at least 256 bytes, plus a private `dist/.static-assets.json` manifest.
Already compressed binary formats are not recompressed. The manifest records
SHA-256 and byte length for each original and encoded representation; it is
written after the artifacts. No new runtime dependency or request-time
compression is required. The existing container COPY boundaries include all
required runtime files.

Only paths actually generated by esbuild in its content-hashed chunk namespace
are marked immutable. A copied file with a hash-looking name does not qualify.
Never overwrite a previously served content-hashed URL with different content;
existing clients may legitimately retain it for a year. Serve the built
distribution as a complete unit. This change does not provide atomic deployment
or retention of old chunks for already-open tabs.

## HTTP behavior

- `Accept-Encoding` negotiates Brotli, gzip or identity, honoring valid q-values,
  explicit refusals and wildcards. Brotli wins equal compression preferences.
  Implicit identity is a fallback; an explicit identity preference participates
  in quality ranking. Missing/empty headers select identity. Malformed supported
  entries are rejected conservatively; duplicate entries use the lowest quality.
  If every available representation is refused, the response is an empty,
  non-cacheable 406. Static negotiation always supplies `Vary: Accept-Encoding`
- Before selecting a sidecar, the server checks the current original bytes
  against the manifest, then checks the encoded bytes. Missing, corrupt or stale
  artifacts fall back to another acceptable verified representation or identity.
  This also catches changed bytes with unchanged length and modification time
- HTML, SPA entry fallbacks, main JS/CSS, and all copied public assets use
  `Cache-Control: no-cache` plus a strong representation-specific SHA-256 ETag.
  Browsers revalidate them before reuse. Verified generated hashed chunks use
  `public, max-age=31536000, immutable`
- Matching `If-None-Match` (including weak comparisons and lists) returns 304
  without a body. Encoding variants have distinct ETags. `If-Match` uses strong
  comparison and takes precedence. `HEAD` returns the same selected metadata and
  length as GET without a body
- Last-Modified/date validators are deliberately omitted: second-resolution
  timestamps can falsely validate a mutable file replaced in the same second
- Byte ranges remain unsupported. `Accept-Ranges: none` is explicit; Range and
  If-Range receive the complete negotiated representation with 200 unless an
  ordinary precondition selects 304/412. No compressed/uncompressed offset mixing
- Hidden metadata and direct `.br`/`.gz` requests are unavailable. Static paths
  remain confined to the distribution, including symlink targets; invalid URL
  escapes, encoded traversal, backslashes and NULs fail closed. Existing
  Host/Origin checks run first; security headers and extensionless SPA entry
  fallback remain in place
- This helper is only called outside `/api/`. Authenticated JSON, authenticated
  content and SSE retain their existing authorization, no-store and encoding
  behavior. The implementation does not apply compression middleware globally

The server still reads and hashes static bytes to validate them. The improvement
is transmitted bytes and browser reuse; it is not a disk-I/O, CPU, latency or
concurrency guarantee. Older distributions without the manifest remain usable
with identity delivery, ETags and conservative cache policy.

## Reproduce and verify

```sh
npm run build
node --test tests/static-build.test.mjs tests/static-assets-http.test.mjs
node tests/static-delivery.browser.mjs
npm run verify
npm run verify:container-files
```

The build test runs the real builder in an isolated fixture and independently
decompresses/verifies its artifacts. HTTP tests use the actual game server,
including malformed/refused encodings, variant validators, conditional HEAD,
Range, source/sidecar corruption, traversal, authenticated JSON and live SSE.
The browser check uses normal Chromium caching and the real built onboarding
app, with WebGL deliberately disabled to isolate delivery; it performs no
network interception and records two ordinary reloads. Its evidence is
`evidence/static-delivery-browser.json`.

For manual requests after `npm start`, use an HTTP client that preserves wire
bytes (avoid curl's `--compressed` when counting encoded body size):

```sh
curl -sS -D /tmp/universe-headers -H 'Accept-Encoding: br, gzip' \
  http://127.0.0.1:4190/main.js -o /tmp/universe-main.br
wc -c /tmp/universe-main.br
# Repeat with the exact ETag from the response:
curl -sS -D -H 'Accept-Encoding: br, gzip' -H 'If-None-Match: "sha256-…"' \
  http://127.0.0.1:4190/main.js -o /tmp/universe-revalidated
```

## Bounded local evidence (2026-10-03)

The original source tree `b349974d` (published as `92fc8b6`) sent 1,274,686
main.js bytes with an
`Accept-Encoding: br, gzip` request, no validator, and another complete 200 body
on a conditional repeat. With this change, actual main.js responses measured:

| Representation | Status | Body bytes |
| --- | ---: | ---: |
| Identity | 200 | 1,275,001 |
| Gzip | 200 | 367,297 |
| Brotli | 200 | 297,148 |
| Brotli ETag revalidation | 304 | 0 |

The small raw-size change comes from the explicit chunk path namespace. In one
actual Chromium onboarding run, the cold page served 505,787 static body bytes
across 22 requests. Each ordinary reload made eight validator requests and
served **zero static body bytes**; other resources were reused from cache.
Resource Timing still counted 2,100 response-header transfer bytes per reload.
This onboarding checkpoint excludes full playable initialization, so it must
not be treated as the whole game's initial download budget.
These are loopback/shared-host delivery observations, not production or
physical-device performance results.
