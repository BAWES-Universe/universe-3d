# Nearby typing: pinned source and bounded acceptance

Source audit recorded 3 October 2026 before implementation. The citations and proposed acceptance below describe that audit, not current passing evidence. See [the implementation contract](NEARBY-TYPING-CONTRACT.md) and [development status](DEVELOPMENT-STATUS.md) for the implemented boundary and subsequent tests.

Bot comparison: `0e1ff05014d4b871ffd94eea744e40c1d1c7df79`; do not treat this as the deployed frontend revision. Standalone seams below are pinned to published Nearby text `BAWES-Universe/universe-3d@b56e7bf09c7e59931dea8386e7e906af4d099fc1`. ## What the source actually does

- **Wire and authority:** `SpaceIsTyping` contains only `isTyping: bool`, repeated character textures, and optional name. Its public envelope adds Space name and sender ID. There is no text body, message/request ID, sequence, timestamp, lease, receipt, or replay cursor. Pusher derives sender ID from the socket, checks joined-Space membership, and back requires that sender in the Space user list and replaces name/textures. These are joined-Space checks, not independently proven spatial authorization. [Schema][schema], [pusher gate][gate], [identity][identity]
- **Audience:** the ordinary bubble joins with `ALL_USERS`; public fanout reaches connected Space members except the exact sender `spaceUserId`, including other tabs of the same account. Neither typing emission nor fanout checks AV consent, media peers, P2P threshold, or SFU state. The same source class also serves meeting/stream spaces; the standalone slice remains ordinary bubbles only. [Join][join], [fanout][fanout], [per-tab identity][tab-id]
- **Sender:** every composer keydown invokes `startTyping()` before inspecting the key or empty content. There is **no human sender throttle/debounce in this inspected path**. The promise schedules stop after 10,000 ms; later keydowns reset it. Enter or an empty pre-keydown composer also sends stop; Shift+Enter stops before returning to insert a newline. A nonempty input/paste alone is not a start trigger; the input handler only stops when empty. Every send-button/Enter/file/link send path calls stop first. [Composer][composer], [idle constant][idle], [empty input][empty], [emit][emit]
- **Composition/focus/close gaps:** no composition listener or IME Enter guard exists in the inspected upstream textbox/composer. Focus handlers only update the world-input focus store. Composer destruction saves its draft but neither clears the typing timeout nor calls stop. Its pending timeout calls the mutable room object, without a captured Space generation; do not copy it as a stale-callback guarantee. [Textbox][textbox], [focus][focus], [destroy composer][composer-destroy]
- **Receiver:** each true event renews a timer keyed by sender `spaceUserId`; it expires after 12,000 ms even if stop is lost. False, received ordinary text, and observed participant departure remove that sender. Own local leave/destroy clears all typing entries and timers and unsubscribes. Leave sets `_space` undefined before teardown and does not explicitly send stop first. [Expiry][expiry], [receive][receive], [peer departure][peer-leave], [leave][leave], [destroy room][room-destroy]
- **Blocked users:** receiver resolves the sender's UUID from current Space users and ignores both text and typing if blacklisted. Unknown UUID does not establish a block. There is no blacklist-change subscription in this inspected room, so an already displayed entry may last until its 12-second timeout; even a blocked sender's stop is ignored. This is frontend suppression, not proven server exclusion. [Blacklist check and receiver][receive]
- **Reconnect/history:** this event is immediate live WebSocket traffic; a destroyed Space skips emission and a closing/closed WebSocket logs and drops it. The room's handover carries messages/drafts, not typing timers. There is no typing replay queue or delivery receipt in the inspected path. “No automatic typing after reconnect” is a proposed explicit standalone guarantee, stronger than merely not finding a queue; the upstream composer timeout has no generation guard. [Space send][space-send], [socket send][socket-send], [handover][handover]
- **Bots are separate scope:** bot clients use the same `SpaceIsTyping` event when admitted to a Space, but behavior code starts it around generation and stops at completion/error, not at human-keyboard idle. Streamed answer bodies are `SpaceStreamMessage`, correlated by response ID; receiving those chunks does not run the ordinary-message typing-clear handler. Separately, scripted external typing inserts a local author-keyed entry without the normal 12-second timer. Do not infer human timing, body privacy, persistence, or safe generation cleanup from these bot paths. [Bot emit][bot-emit], [bot start][bot-start], [bot finish][bot-finish], [bot error][bot-error], [stream schema][stream-schema], [external typing][external], [script adapter][script]

## Standalone authority seams and required adaptation

Everything in this section is a proposed acceptance contract, not an upstream guarantee or an implemented feature.

1. **Use Nearby text authority.** Gate typing on configured text plus all-member authority and an active ordinary-bubble context. Reuse the exact `connectionEpoch`, `roomId`, `bubbleId`, `memberId`, and `membershipRevision` checks and live session/room authorization; a stale request must never be rebound to the latest context. Use `conversationRecipients`, independently of AV consent. Preserve mute/ban/access/status/area exclusions already applied by Nearby. Client context ordering also respects monotonic `contextRevision`. [Server context/capture][local-context], [membership audience][local-audience], [client context][local-client]
2. **Bind a lease to a source stream, not an account or cookie.** Same-cookie tabs have distinct SSE client objects and epochs. Keep only bounded transient metadata for `(source client/epoch, account, room, bubble, member, membership revision)` plus sequence/expiry and admitted recipient-stream identities. Emit a server-derived opaque source-stream ID; never accept caller-selected author, recipients, expiry, or stream identity. Display at most one entry per remote account while **any** admitted source stream for that account remains live. Suppress own-account typing in the UI; do not clear sibling activity when one tab stops, sends, leaves, or disconnects. This intentionally differs from upstream per-tab avatars. [Connection epochs][local-context], [SSE registration][local-sse]
3. **Sequence before arrival order.** Each source epoch has a strictly increasing safe-integer sequence shared by start/refresh/stop requests. A delayed or duplicate lower/equal sequence is a no-op and never extends expiry. Retain a sequence high-water mark after stop/expiry for the remaining epoch; removing the active lease must not permit an old start to resurrect it. A renewed lease's timer checks captured epoch/context/sequence or lease identity before deletion. Text completion/ack callbacks likewise cannot clear activity begun later. Sequence metadata is not a text receipt and must not consume the text receipt map or rotate its 128-message budget.
4. **Validate across the body/read/write boundary.** Capture eligible source epochs and actual target SSE objects before awaiting a bounded body, as Nearby text already does. Revalidate the sender, sequence, live source epoch, session, admission, room authorization and membership revision after parsing, and each target's live epoch/admission immediately before write. Do not use room-wide `emitRoom`/account-wide `emitUser` as a typing authority. Later sockets, newly admitted recipients, and rejoined members cannot inherit the pending event. A newly joined person sees only a newly accepted activity event. [Existing snapshot/fanout pattern][local-send], [HTTP boundary][local-http]
5. **Retire immediately at lifecycle seams.** Add typing retirement to individual SSE close (currently it only removes the client), token/session retirement, epoch rotation, session expiry/logout, room change/deletion, access revoke, kick/ban/mute, lost admission/presence lease, audience revision change, excluded area/status, authority failure, and server close. Existing `retire(token)` rotates every client under that token; it is insufficient by itself for one-tab close while siblings preserve the account admission. Clear the source's contribution at still-authorized recipients without sending into a new audience; recipient/context invalidation clears local entries. Do not rely on the existing 15-second host heartbeat for a 12-second typing expiry or prompt explicit revocation. [Host lifecycle][local-lifecycle], [SSE close/heartbeat][local-sse], [admission continuity][local-admission]
6. **Bound ephemeral state and input.** Suggested review baseline: first real activity starts immediately; later start/refresh emissions at most once per 2 seconds per stream, only after fresh input/composition activity; idle stop 10 seconds after last real activity; remote lease no longer than 12 seconds after the last accepted fresh start. Strict JSON request fields are the five context fields above plus `sequence` and `isTyping`; cap request bytes at 2 KiB and body wait at 2 seconds. Suggested server account quota: burst 8, refill 2 starts/second; at most one active lease per source epoch, 64 per account and 8,192 globally, with bounded recipient contribution storage. A valid newer stop for an existing lease bypasses start-rate exhaustion and cannot add capacity; repeated stops have no fanout. Cleanup never waits for a quota. Numbers other than 10s/12s are standalone policy proposals, requiring implementation tests, not source facts.
7. **No transcript side effects.** Typing carries no draft/message body, attachment, request receipt, read status, history row, unread increment, sound, analytics payload, durable storage, normal log entry, or reconnect/retry queue. A transport acknowledgement may report acceptance only; no message receipt is retained. Failed typing sends are dropped. Reconnect, restored drafts, context refresh, panel reopen, and text retry cannot auto-start typing; require a new real input/composition action. Stop/expiry metadata may exist only within the active connection/context lifetime.
8. **UI lifecycle is explicit.** Start only in the focused, visible Nearby composer for the selected live stay. Actual `input` (including paste) and IME composition activity count; focus alone does not. Empty non-composing input, send attempt, close/Escape, selecting an ended stay, switching tab/channel, document hide, destroy, or authority loss stops and cancels timers. Suggested focus-out debounce is 150 ms to tolerate internal focus changes; close/send/hide do not wait. Composition Enter never sends; Shift+Enter remains a newline. Generation guards reject stale HTTP/timer/render callbacks. Update a separate text status without rebuilding the composer, moving focus, scrolling the timeline, or launching Express/avatar motion. [Existing composer seams][local-ui], [app event guards][local-events]

**Personal-block gap:** the inspected standalone store/social path has room moderation but no source-like personal blacklist. Test room mute/kick/ban now; do not certify personal-block parity. If a personal-block authority is added within separately approved scope, enforce it for typing start/refresh and immediately clear blocked contributions, including both sides of send/receive policy as specified by that feature. Merely renaming room ban is not a substitute. [Standalone member schema][local-store]

## Concise acceptance matrix

These are acceptance requirements recorded by the source audit. The audit itself executed none; later implementation evidence is reported separately, without treating this table as a pass list.

| Case | Required observable outcome |
|---|---|
| Same bubble A/B/C, all AV off; D outside bubble/E other room | A typing reaches B/C only; no permission prompt or P2P/SFU dependency |
| Focus, arrow/modifier keys, restored draft, panel reopen | No typing start without real new activity |
| Rapid ordinary input/paste | Immediate first start; refresh throttled to proposed 2s; no draft content transmitted |
| IME start/update/end, Enter, Shift+Enter | Composition counts as activity; IME Enter never sends; Shift+Enter newline; normal Enter sends once and stops |
| Empty input/send click/send failure | Own stream stops; valid stop not blocked by exhausted start quota; no sibling lease cleared |
| Stop lost / sender crashes | Receiver removes by 12s after last accepted start; timer cannot remove a subsequently renewed lease |
| 10s idle | Sender emits stop and cancels refresh; no timer invents further activity |
| A1 and A2 share cookie or use separate sessions | B displays one A; A1 stop/close/send leaves A2 contribution; last active stream stop removes A |
| start seq 1 delayed behind stop seq 2; duplicate seq 2 | Neither stale start nor duplicate extends or resurrects typing, including after expiry |
| Old stop/timer/HTTP reply after new input or epoch | New valid activity survives; old activity never enters a new context |
| B joins/rejoins/reconnects after request begins | No queued/snapshotted typing inherited; only new admitted activity can appear |
| A source socket closes, siblings keep account member | Only that source lease clears promptly; account membership continuity cannot retain it |
| Leave/new room/new bubble/new member/audience revision/epoch rotation | Old contributions clear; all old envelopes fail; carried drafts do not auto-start |
| Reconnect while composer still holds text | Local/remote stale state clears; no replay, retry queue or automatic start |
| Sender/recipient session expires, room deleted/access revoked, kick/ban/mute | No unauthorized emission; affected entries clear without waiting for account disappearance |
| Silent/meeting/stage/audience or excluded status | No ordinary Nearby typing; no leak through other chat/media routes |
| Authority read throws between capture and write | Fail closed; no subsequent emission or stale indicator restoration |
| Forged author/targets/expiry/stream ID, bad bool/sequence, oversize/slow body | Reject without allocation, delivery, text receipt, or sensitive logging |
| Account burst/state capacity exhausted | Bounded failure; stops, expiry, disconnect cleanup still work; text budget unaffected |
| Close/Escape/channel/tab/ended-stay/document-hide/blur | Proper own stop/cancel; no movement/Express; delayed blur cannot stop refocused newer activity |
| Incoming typing while scrolling/focused elsewhere | No focus/scroll theft, sound, unread count, transcript mutation, or draft replacement |
| Feature/text disabled; server restart/full reload | Typing route/UI inactive when disabled; no recovered typing/history after restart |
| Source blacklist; standalone room moderation | Source suppression/12s fallback documented; no false personal-block parity claim |
| Source bot and external scripted typing | Audited separately; no bot generation, streaming, script identity or synthetic user typing introduced |

Evidence limits: captured pinned code only; no live source/configuration access, production credentials, browser exercise, source test run, or new repository write. This source evidence is distinct from the later implementation tests.
