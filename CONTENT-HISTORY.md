# Embedded content and browser history

Embedded room content can remain open underneath Chat, Places, Help, Express and quick actions. Opening or dismissing a foreground surface keeps the existing iframe node alive, including an unsubmitted form inside it. Nested foreground surfaces retain their visible underlying panel during Back and Forward. Primary Build/Explore switching stays exclusive. If Return to world closes content underneath a foreground panel, a later UI dismissal preserves that closed background. It removes the foreground layer in-place rather than traversing to an older content entry; an explicit browser Back may still visit and reauthorize that historical entry.

History entries contain known surface names, the room identifier and an opaque, tab-local content key. They do not contain the provider URL, iframe document, typed form values, credentials or action response. Replaying history suppresses the panels' normal history-writing callbacks, including a close followed immediately by opening another surface.

Return to world, Close this panel, and closing the content layer with Escape intentionally dispose the iframe. Forward can reopen the last available content reference only while that reference remains valid in the current tab, room and account. Reopening sends a fresh action authorization request and creates a new frame; it does not recover a disposed form. Failed authorization and cancelled or superseded restores do not create frames. Travel, lost room readiness, changed accounts, and changed/removed actions invalidate stale references.

## Verification

`node --test tests/surface-history.test.mjs tests/embedded-history-dom.test.mjs` covers the history policy, replay callback suppression, pending Back/open sequencing, nested image/profile underlays, explicit iframe disposal, no-focus background restoration, delayed restore cancellation and room/account/action boundaries. The DOM tests use a small ownership model; they do not claim real browser loading.

`npm run build && node tests/content-history.full.mjs` runs the actual bundled game, a temporary in-memory local server, and a locally intercepted HTTPS form. It compares the real iframe node, request/load counts and natively typed form value while exercising dock/keyboard navigation and native browser Back/Forward. It also exercises explicit content disposal, fresh authorized reopening, denied reopening, an interrupted restore, exclusive Build/Explore switching, nested Custom images, and room travel. A separate regression closes content under Chat, then uses native middle-pan, Chat Close/reopen, Follow/Reset and another Chat Close; none may reload content. Explicit native Back afterward must reauthorize the historical content, and Forward must return to its closed state. A separate two-frame case uses native opens plus a labeled server-scene revocation fixture: removing the latest action must leave the earlier iframe and typed form alive through foreground Close and Back/Forward; intentional all-close still disposes it, without restoring the revoked action.

The isolated history test uses the native Chat dock toggle and Places Escape route. At the original layout baseline, embedded content covered those panels' Close buttons; this history change does not itself fix that separate layout issue. The combined layout/history runner `npm run test:browser:hud` sets `CONTENT_HISTORY_POINTER_CLOSE=1` and requires the actual Chat/Places Close buttons. It retains every iframe, form-state, authorization and history assertion.

The browser proof uses Chromium software WebGL at 1920×1080. It is not a physical-device, external-provider embedding, authentication, or cross-browser certification. Keyboard events handled inside a cross-origin iframe do not bubble to the game; use the parent application's controls to navigate its layers. Releasing a removed latest action cannot invalidate the group key while an earlier iframe remains live. After intentional all-close, a revoked latest action is never reopened, and the application does not reconstruct an older multi-tab session. Intentional reopening supports only the latest valid reference. Existing room-draft and saving guards, avatar rendering, media authorization and server navigation are not rewritten by this change.
