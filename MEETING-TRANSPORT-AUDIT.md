## Routes kept distinct

1. **Generic Space / proximity meeting:** `ProximitySpaceManager` handles server-requested bubble joins through `ProximityChatRoom.joinSpace`. The latter forwards name, filter and media properties to `SpaceRegistry`; its `isMeetingRoomChat` flag affects UI/session markers, not transport. [Proximity manager, lines 15–34](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/WebRtc/ProximitySpaceManager.ts#L15-L34); [chat join, lines 970–1023](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/Chat/Connection/Proximity/ProximityChatRoom.ts#L970-L1023).

2. **Named native meeting area:** `type: "livekitRoomProperty"` chooses `property.roomName`, or `property.id` when the name is blank/whitespace. It derives `slugify(shortHash(scene.roomUrl) + "-" + roomID)`, then joins `FilterType.ALL_USERS` with camera, microphone and screen properties. With chat disabled it directly joins `SpaceRegistry`; otherwise it joins through the chat wrapper. Both routes reach the same backend manager. Matching names across areas of the same room URL share the derived identity; identical names in different room URLs are not automatically cross-room meetings. [Area entry, lines 874–943](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/Phaser/Game/MapEditor/AreasPropertiesListener.ts#L874-L943); [identity helper, lines 15–17](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/libs/shared-utils/src/Jitsi/slugify.ts#L15-L17).

3. **Direct LiveKit area:** no separate unconditional direct-SFU entry is established by the examined route. The editor's LiveKit-named property is route 2, including its chat-disabled branch. Its schema contains name, trigger text, entry audio/video mute, disable-chat and admin-tag fields, with no transport override. Actual LiveKit connection is downstream of a server switch and private invitation. Do not implement a forced-SFU policy merely because this property has “LiveKit” in its name. [Schema, lines 44–50 and 193–199](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/libs/map-editor/src/types.ts#L193-L199); [invitation handling, lines 52–83](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/Livekit/LivekitConnection.ts#L52-L83).

4. **Stage / audience:** `speakerMegaphone` and `listenerMegaphone` resolve a shared room-prefixed speaker name and join `LIVE_STREAMING_USERS`. Speaker entry calls `space.startStreaming()`; audience entry does not. Chat flags change the join wrapper, not transport. Backend publisher filtering uses `megaphoneState`, but the transport count remains all Space entries. [Stage/audience entry, lines 1366–1462](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/Phaser/Game/MapEditor/AreasPropertiesListener.ts#L1366-L1462); [backend filter/count, lines 279–285 and 622–647](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/Space.ts#L622-L647).

5. **Cross-room megaphone:** settings supply a shared URL-derived slug, rather than the native meeting's room-URL-prefixed name. `GameScene` joins it through `BroadcastService`, which uses `LIVE_STREAMING_USERS` and media properties. Metadata `isMegaphoneSpace` labels the stream; it is not an SFU selector in the manager. Shared backend/world namespace and permissions still matter; do not infer global unrestricted broadcast. [Settings handling, lines 2113–2159](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/Phaser/Game/GameScene.ts#L2113-L2159); [broadcast join, lines 25–33](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/Streaming/BroadcastService.ts#L25-L33).

External Jitsi/BBB and iframe providers are separate integrations, not evidence of native forced LiveKit.

## Transport and exact configuration

- Backend `SocketManager.handleJoinSpaceMessage` constructs `Space`, which unconditionally creates `new CommunicationManager(this)`. No area-type or meeting-force flag is passed. Media properties choose initial `WebRTCState`; absence chooses `VoidState`. [Backend join, lines 1281–1296](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Services/SocketManager.ts#L1281-L1296); [Space constructor, lines 45–59](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/Space.ts#L45-L59); [initial selection, lines 35–46](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/CommunicationManager.ts#L35-L46).
- `MAX_USERS_FOR_WEBRTC` defaults to **4**, independent of `MAX_PER_GROUP` default **4**. Upgrade requires `getAllUsers().length > MAX_USERS_FOR_WEBRTC` and available LiveKit. Under ordinary proximity admission, the default group cap can prevent a bubble reaching the upgrade count; trusted follow/special joins must be assessed separately and are not asserted to obey that ordinary cap. Named meeting Spaces do not use Group's capacity check. Implementing the requested “above five” rule through this threshold policy requires effective threshold **5**, and ordinary six-member admission requires a configured group capacity of at least **6**. These are conditional derived requirements, not inferences about deployed settings from the owner's observation. [Defaults, lines 64–67 and 155–161](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Enum/EnvironmentVariableValidator.ts#L155-L161); [policy, lines 29–43](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/Policies/TransitionPolicy.ts#L29-L43).
- Available means Admin API advertises `api/livekit/credentials: "v1"`, **or** all three `LIVEKIT_HOST`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` are nonempty. It is a configuration capability check, not health/readiness proof. Admin capability takes precedence in state creation; that branch requires `playUri` and fetches credentials through the configured Admin API. No secret values are needed for a configuration audit. [Availability, lines 17–21](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/Services/LivekitAvailabilityService.ts#L17-L21); [factory, lines 47–72](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/States/StateFactory.ts#L47-L72).
- Membership events evaluate all Space entries regardless of media mute. Upgrade is immediate selection; return at/below threshold is scheduled after **20,000 ms**, then revalidated. Source dependency injection can replace that delay/policy, but production Space construction supplies no override. No per-meeting threshold/force setting was found on this path. [Manager, lines 81–115, 158–200, 217–272](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/CommunicationManager.ts#L158-L200).
- State lifecycle sends the switch, initializes the new state and finalizes the previous state after **5,000 ms** by default. The frontend constructs the selected WebRTC/LiveKit state, receives the LiveKit token invitation and joins. This timer is not proof of an acknowledged, successful or single-audible-route handoff. [Lifecycle, lines 24–77](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/back/src/Model/Services/StateLifecycleManager.ts#L24-L77); [client switch, lines 103–151](https://github.com/BAWES-Universe/workadventure-universe/blob/bae18306bdfa63e58cd4124b1a3b5b290b61c286/play/src/front/Space/SpacePeerManager/SpacePeerManager.ts#L103-L151).

The existing opt-in standalone model's `force-sfu-target` remains an explicit requested product target, **not pinned native-meeting parity**. This audit does not authorize turning on SFU, replacing meeting topology, or copying unreviewed grants/cleanup behavior.
